## 2. 产品快照

TypeWords 是本地优先的英语打字练习站，线上 [typewords.cc](https://typewords.cc)。GPL-3.0。

| 能力 | 现状 |
|------|------|
| 单词练习 | 跟写 / 听写 / 自测 / 默写；智能学习、自由、随机复习、自定义 flow |
| 文章练习 | 逐句跟打 + 默写，课文音频 + 时间轴 |
| 词本 | 收藏、错词、已掌握（已掌握自动跳过） |
| 记忆 | FSRS（`ts-fsrs`），按错误次数评级 |
| 数据 | IndexedDB 本地；可选用户自配 Supabase 同步 |
| 词库 | 官方 JSON 静态文件；自定义 txt / json / xlsx 导入 |

GitHub 仓库 2023-08-03 创建，原名 typing-word。当前 `master` 的 git 根提交是 **2026-01-15**（迁 Nuxt 时旧 Vue 历史被压成一颗）。本 clone 只带 CET-4 和新概念 1，完整词库在生产 CDN。

## 5. 数据怎么存

### 5.1 官方词库（只读 JSON）

```
public/list/word.json          单词书目录
public/list/article.json       文章书目录
public/dicts/{language}/word/{url}
public/dicts/{language}/article/{url}
```

加载：

```
GET /dicts/en/word/CET4_T.json      → Word[]
GET /dicts/en/article/NCE_1.json    → Article[]
```

`env.ts` 里 `RESOURCE_URL` 为空时走站点根路径；生产可指到 CDN。`url` 只是文件名。

单词对象（磁盘与内存同一套结构）：

```
Word {
  word, phonetic0, phonetic1,
  trans[{ pos, cn, frequency? }],
  sentences[{ c, cn }],
  phrases[{ c, cn }],
  synos[{ pos, cn, ws[] }],
  relWords{ root, rels[] },
  etymology[{ t, d }],
  custom?, id?
}
```

文章对象在磁盘上主要是原文，不预切 token：

```
Article {
  title, titleTranslate, text, textTranslate,
  audioSrc, lrcPosition[][],
  newWords?, questions?, quote?, question?
}
```

练习时 `genArticleSectionData()` 把 `text` 切成 `sections → Sentence → ArticleWord`。

### 5.2 用户数据（IndexedDB）

`idb-keyval`，值是 JSON 字符串：

| Key | 内容 | 版本常量 |
|-----|------|----------|
| `typing-word-dict` | 词书列表、进度、FSRS、笔记 | `SAVE_DICT_KEY` v4 |
| `typing-word-setting` | 全部设置 | `SAVE_SETTING_KEY` v23 |
| `PracticeSaveWord` | 单词练习会话（紧凑：只存 word 字符串） | v2 |
| `PracticeSaveArticle` | 文章练习光标 | v1 |

写入官方词书前会 `shakeCommonDict()`：

- 官方词典：**丢掉 `words` / `articles`**，只留元数据 + `lastLearnIndex` 等进度。
- 自定义 / 系统词本（收藏、错词、已掌握）：完整 `Word[]` 留下。
- 自定义文章的 `sections` 不存，下次再生成。

因此：**改官方 JSON 不会自动改用户已学进度；改 Word 字段要同时改导入、升级、练习缓存。**

### 5.3 其它本地数据

| 位置 | 用途 |
|------|------|
| `base.fsrsData` | `Record<单词, FSRS Card>` |
| `base.noteData` | `Record<单词, 笔记>` |
| `localStorage PracticeFlowV2` | 用户自定义练习 flow |
| `localStorage supabase_config` | 用户自填的同步配置 |
| IndexedDB `typing-word-files` | 自定义文章音频 Blob |
| IndexedDB `type-words-backup-*` | 哈希快照备份链 |

可选同步到用户自己的 Supabase 表 `typewords_data`（dict / setting / practice_word / practice_article）。自定义音频的文章会禁用同步。

启动：`layouts/default.vue` → `useInit()` → 读 IndexedDB → 可选和远端对账 → `$subscribe` debounce 1s 写回。

## 6. 单词练习引擎

这是代码密度最高、也最容易改坏的一块。目录：`app/core/composables/practice-words/`。

```
createStudyTask()          今日新词 + FSRS 到期复习
  → usePracticeWordSession 会话：缓存恢复、错词、出题
    → createPracticeWordNavigator  flow 游标（唯一位置指针）
    → usePracticeWordTyping        键入状态机
    → usePracticeDisplayPolicy     是否遮罩单词 / 显示翻译
页面 practice-words/[id].vue 只负责加载词典和接 UI
TypeWord.vue = WordTypingCore + WordIdentifyPanel + WordMetaPanel
```

练习模式 `WordPracticeMode`：System / Free / IdentifyOnly / DictationOnly / ListenOnly / Shuffle / Review / WordsTest / Custom。

Flow v6（可序列化）：

```
Flow → Node（词源：新词 / 复习 / 错词 / 当前）
     → Step（跟写 / 拼写 / 听写 / 默写 / 自测）
     → wordLoop（默认 7 词一组）
     → onEnd（清错词、收藏、报告、下一步）
```

内置 flow 在 `practice-flow-config.ts`。改「怎么练」优先改 flow 配置，不要在页面里写死阶段顺序。

FSRS：错误次数映射 Easy / Good / Hard / Again，阈值在设置里（`fsrsEasyLimit` 等）。

## 9. 改造时的硬约束

1. **用户存档有版本。** 改 dict/setting/practice cache 的形状，必须写 upgrade，并 bump 对应 `version`。老用户 IndexedDB 里是 v4 / v23 / practice v2。
2. **官方词表不进 IndexedDB。** 只存进度。不要假设用户机器上有完整 CET-4 JSON。
3. **系统词本 id 不能乱改：** `wordCollect` / `wordWrong` / `wordKnown` / `articleCollect`。
4. **练习会话缓存是紧凑格式**（`wordsStr` 而不是完整 Word）。改 Word 主键或拼写，要想好缓存怎么失效。
5. **文章 `sections` 是运行时生成的。** 不要把它当成持久字段设计功能。
6. **`$ref` 与标准 `ref` 混用。** 改旧页面时保持原风格或整页迁完，不要同一函数里混两种。
7. **没有测试。** 动 `practice-words` 至少要手工走完：System 新词跟写→听写→默写、错词清空、刷新恢复、切词书。
8. **本仓库词库不完整。** 本地只有 CET-4 + NCE1，不要按 README 里的全量词库写死路径。
9. **i18n 默认中文、无 URL 前缀。** 新字符串必须进 14 个语言文件（或至少 zh/en）。
10. **同步按 `updated_at` 比新旧。** 本地乱写时间会覆盖云端。

已知债（不一定这次改）：

- `core/utils/index.ts` 过大。
- 文章练习未模块化。
- `Toast.warning('未现实')` 笔误。
- TypeScript 未开严格模式。
- 例句练习 composable 有 `@deprecated`。
- 提交信息大量 `wip` / `fix`。

## 14. TW-002 方案：默写开关

### 14.1 动机

雅思词里不少只需读懂、不必会默写。现在智能学习把默写写死在流程里，新词一律 跟写 → 听写 → **默写**，没有总闸。

复习阶段点「认识」会进 `excludeWords`，后面听写/默写会跳过该词；**新词阶段没有自测**，所以不能按词跳过默写。这次用设置开关解决：这轮学习只需认读时，整段关掉默写。

### 14.2 现状

```
新词：跟写 → 听写 → 默写     ← 无法跳过
复习：自测 → 听写 → 默写     ← 点「认识」可跳过该词后续阶段
```

单词设置有「例句练习」开关，没有默写开关。

不要和下面这些搞混：

| 已有 | 作用 |
|------|------|
| `setting.dictation` | 文章/例句遮单词，不是流程开关 |
| Ctrl+I | 当前词临时显示/遮罩 |
| 首页「默写」模式 | 整场只默写，独立入口 |

### 14.3 要做成什么样

单词设置里、和「例句练习」并列：

- 标题：默写
- 说明：关闭后，智能学习和复习不再进入默写；跟写、听写、自测不变。适合只需认读的词。
- 默认：**开**
- 新字段 `wordPracticeDictation`，默认 `true`，不复用 `dictation`

关掉后：

- System 新词：跟写 → 听写
- System / Review 复习：自测 → 听写
- 首页单独「默写」模式仍在
- 自定义 flow 里的默写 step 这次不动

按词「只需认识」不做。全局关掉即所有词跳过默写阶段。

### 14.4 怎么改（开工时）

1. `stores/setting.ts` 增加字段，`SAVE_SETTING_KEY.version` +1，老数据缺省为 `true`
2. `WordSetting.vue` 加 Switch
3. 内置 system / review flow 在解析时若开关为关，去掉 `templateId === 'dictation'` 的 step
4. 练习中途改开关：下次进入练习或切阶段再生效
5. i18n 至少 zh / en

## 15. TW-004 方案：登录 + 官方云同步

### 15.1 目标

- **不登录也能练**，进度仍在本机 IndexedDB。
- **登录后**把 dict / setting / practice_word 同步到官方 Supabase，换设备登录能拉回来。
- 继续整包 JSON blob，不把 FSRS、错词拆成多表。

### 15.2 沿用什么

现有 `useDataSyncPersistence`：`updated_at` 比新旧、本地 debounce 写入后再 upsert。缺的是「谁的数据」和「官方项目」。

当前 upsert 冲突键是 `onConflict: 'type'`，全表每种 type 只有一行，**必须改成 `(user_id, type)`**，否则所有用户会互相覆盖。

### 15.3 后端

官方一个 Supabase 项目。前端 `runtimeConfig.public` 提供 `supabaseUrl` + `supabaseAnonKey`（anon，不是 service_role）。

**Auth：** Supabase Auth，邮箱+密码（可再加 magic link）。OAuth（GitHub 等）可二期。

**表 `typewords_data`：**

```
user_id uuid not null references auth.users
type text not null          -- dict | setting | practice_word | practice_article
data jsonb not null
data_version int
updated_at timestamptz
primary key (user_id, type)
```

**RLS：** 只允许 `auth.uid() = user_id` 的 select/upsert/delete。

payload 仍走 `shakeCommonDict()`，官方词表不上云。

用户自填 URL/Key 可保留为高级项（覆盖官方项目）；默认用官方配置。未登录则不同步。

### 15.4 前端

1. **会话：** `userStore`（解开现有 `userStore.init()` 注释那条线）。启动时 `getSession()`，`onAuthStateChange` 后开/关同步。
2. **UI：** 设置页「数据同步」改成登录/注册/退出/当前邮箱；侧栏可显示登录状态。不要强制登录墙。
3. **同步时机：** 与现在相同——init、visibility 回到前台、Pinia `$subscribe` debounce。仅 `session` 存在时打云。
4. **首次登录合并：**
   - 云空、本地有 → 推上去
   - 本地空、云有 → 拉下来
   - 两边都有 → 用已有 `BackupGateDialog` / 冲突弹窗，让用户选「用云端 / 用本机并覆盖云」；不要默默 last-write-wins
5. **退出登录：** 可继续用本机数据；不自动清空 IndexedDB。提供「退出并清除本机进度」可选。
6. **离线：** 照常写 IndexedDB；恢复网络且仍登录再 sync。

练习页、词库加载、FSRS 都不改读写路径，只改 persistence 是否带 `user_id`。

### 15.5 不做

- 必须登录才能打开 `/words`
- 方案 C（服务端算学习任务）
- 实时协作、多端同时练同一本的 OT
- 把密码 RSA 那套做成主登录（已有 `rsa-password` 可忽略，走 Supabase Auth）

### 15.6 开工顺序

1. 建官方项目、表、RLS、Auth
2. env 注入 URL/anon key
3. 改 upsert 冲突键 + 请求带 user
4. 登录 UI + session
5. 首次冲突走现有备份弹窗
6. 设置页替换「自己填 Key」为默认官方同步
